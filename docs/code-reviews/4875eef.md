## A. Local audit findings (code-reviewer)

### Should fix
1. **Misleading security copy.** `DataroomLoadingProgress.jsx` shows time-driven fake stages ("Establishing secure
   connection…", "Verifying access permissions & security policies…", "Loading folder structure…"). They do not
   track real work, and progress stalls at 95% on a slow API. Use neutral copy, or drive the stages from real events.

### Minor
2. **The loading screen rarely shows for a dataroom.** `ShareLinkViewerPage.jsx:406` checks
   `publicMeta?.target_type === 'dataroom'`, but `publicMeta` comes from a separate async fetch and is `null` on first
   paint, so the generic skeleton shows first. Verify the branch fires, and add a page-level test.
3. **Logo URL not validated.** `publicMeta.resolved_brand_logo_url` goes straight into `<img src>`. `PdfJsViewer`
   uses `isSafeUrl`. The value is server-controlled, so confirm backend validation or add the check.
4. **Derived state in an effect.** `stageIndex` is computed from `progress` in a second `useEffect`, causing an extra
   render. Compute it inline. `stages` is rebuilt every render and the timer ticks every 100 ms.
5. **Dark-mode classes are inconsistent.** The icon wrapper has `dark:` variants, but the card, title and background don't.
6. **`shared-ui` chunk.** Re-verify the doc's "100% isolated" and "5 requests" claims with a fresh `npm run build`.
   `LanguagePicker` pulls i18n code into `shared-ui`, so watch for circular-chunk warnings.
7. **Thin tests.** The test hard-codes the initial `15%` and only checks that progress grows. It does not cover stage
   text changes, the logo branch, or the page-level lazy and Suspense fallback.

## Proposed Additions to Long-Term Memory
*Pending user approval; not yet appended to `docs/tech_stack_guidelines.md`.*

- [ ] Issue: The loading UI shows time-based fake stages ("Verifying access permissions & security policies…") that don't reflect real work.
  Prevention Rule: Don't write progress or status copy that claims a security or verification step unless a real event drives it. Use neutral wording for simulated progress.
- [ ] Issue: The page-level loading branch depends on `publicMeta`, which loads asynchronously, so it may not run on first paint.
  Prevention Rule: When a loading UI branch depends on async data, test that the data is available at the moment of the branch, and add a page-level test.
- [ ] Issue (from B1): New `React.lazy` viewers were added with `Suspense` but no error boundary, so a failed chunk import can unmount the tree.
  Prevention Rule: Every `React.lazy` + `Suspense` boundary on a public route needs an error boundary with a retry or reload action, plus a test where the dynamic import rejects.
- [ ] Issue (from B2): The docs diagram kept intermediate build numbers after the table was updated.
  Prevention Rule: When updating measured figures in a doc, update every diagram, table and prose mention in the same change, or label them with the build they come from.
