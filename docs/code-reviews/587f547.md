## Verdict

## What Checks Out
- `remove_dataroom_content` groups associations by backing `Document`, which removes the order-dependent skip.
  Deletion now uses `ddoc_ids_to_remove`, so documents inside deleted folders are included.
- `file_size > 0` is enforced in the tool schema and the client.

## Findings

### Medium
1. **`_normalize_upload_path` guesses file vs. folder from the extension**
   ([client.py](../../mcp-server/coneshare_mcp/client.py)).
   - A folder such as `reports.2024` (with an extension-less file name), or `backup.pdf` when uploading a PDF,
     is rewritten as if it were a file path, so the upload can land in the wrong location.
   - No `..` or empty-segment check on the client; the backend must enforce it (cf. Rule 8). Backend rejection of
     traversal in `path` was not confirmed.
   - Suggestion: treat `path` strictly as a destination folder, never infer a file name. Add tests for dotted
     folder names and `../`.

### Low
2. **Empty `dataroom_document_ids: []` is sent for folder-only removals** (`remove_content_from_dataroom` in
   `client.py`). It works today because `RemoveContentSerializer` allows empty lists and requires at least one
   non-empty list, but the client relies on that. Suggestion: omit empty optional keys; add a folder-only test.
3. **`search_documents` is commented out instead of removed or feature-flagged**
   ([documents.py](../../mcp-server/coneshare_mcp/tools/documents.py)). Dead code remains, and
   `client.search_documents` likely does too. Suggestion: delete it or gate it behind a flag, and keep the
   README/docs consistent.
4. **`Document.id` fallback in `remove_dataroom_content` removes all associations of that document in the room**,
   including linked ones. The backing file is only deleted when no other reference survives, which is correct.
   Suggestion: confirm there is a test with one document linked twice in a room (direct upload + linked reference).

## Proposed Prevention Rules (pending approval for `docs/tech_stack_guidelines.md`)
- Define API path parameters as either a folder or a full path, never both. Do not infer which from extensions.
  Reject `..` and empty segments, and test folders that contain dots.
- Clients and tools should omit empty optional payload keys. Add a contract test for each single-key variant.
